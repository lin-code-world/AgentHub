# 反代网关：桌面 exe 内置网页控制台（移除号池同步与远程实例）设计方案

日期：2026-10-27
状态：已实施（2026-10-28）

---

## 一、目标

一台 Windows 电脑双击运行 exe，启动反代网关。这台电脑的桌面窗口可以完整操作；局域网内其他电脑用浏览器访问它的管理地址，同样可以增删改查。**不考虑 Docker 场景。**

最终形态：

- **桌面窗口**：和现在一样，登录、发号、改配置、签到、刷新额度、OAuth 登录、IDE 切号全部可用。
- **浏览器**：访问 `http://<这台电脑的IP>:<管理端口>`，输入管理令牌后，除了“必须依赖本机”的操作（OAuth、IDE 切号、ZCode 设备操作、打开本机目录），其余功能与桌面端一致。
- 两边操作的是同一个进程、同一份数据库，数据天然一致，不存在同步与迁移。

---

## 二、整体架构

一个 exe 进程同时提供三个服务：

```
exe 进程
├── 反代数据面    :<反代端口>        /v1/chat/completions、/v1/messages、/v1/responses、/v1/models
├── 管理 API      :<反代端口 + 1>    /api/capabilities、/api/rpc、/api/events、/api/status
├── 网页控制台    :<反代端口 + 1>    同一套前端静态文件，浏览器打开即用
└── 桌面窗口      IPC                与现在完全一致
```

- 管理端口 = 反代端口 + 1，随反代端口设置自动变化；反代端口为 65535 时提示用户改端口。
- 管理服务与网关服务在同一进程内，任一停止都不影响另一个（除了进程退出）。
- 桌面窗口与浏览器共用同一份数据目录、同一套命令实现。

## 三、访问与鉴权

### 3.1 管理地址

- 管理服务始终监听 `0.0.0.0`，**不受反代数据面的 `bind` 设置影响**（反代默认只绑 `127.0.0.1`，管理服务仍可局域网访问）。
- **注意**：反代数据面默认只绑本机。如果局域网其他机器还要直接调用 `/v1` 接口，需要把反代 `bind` 改成 `0.0.0.0`；只开浏览器管理则不用改。
- 地址格式：`http://<本机IP>:<管理端口>`，默认管理端口 9528（反代默认 9527 + 1）。
- 桌面端「设置」里显示当前管理地址与令牌，可一键复制。
- Windows 防火墙首次监听会弹提示，需要用户允许专用网络访问；文档与界面要提示这一点。

### 3.2 令牌与登录会话

- 只有一个管理令牌，用户可以在设置页修改，**不允许清空**；首次启动自动生成 24 字节随机十六进制串。
- 手动设置的令牌至少 16 位，界面提示“建议使用随机串，不要用常见密码”。
- 令牌加密存配置（与 WebDAV 密码同机制），不写日志。
- **令牌从不出现在网络上**，只用于登录时对公钥交换做签名。
- 登录用 **ECDH 临时密钥协商**：双方各生成一次性密钥对，交换公钥，各自算出同一个会话密钥。**会话密钥不在网络上传输**。
- 公钥交换由令牌签名保护：没有令牌无法替换公钥，因此即使没有 HTTPS，主动中间人也无法把双方拆成两段。
- 会话有效期 12 小时，由服务端强制；浏览器把 `sessionId`、会话密钥与登录时间存 localStorage，多标签页共享，关标签页或重启浏览器仍保留。
- 到点后服务端拒绝请求并关闭 SSE，浏览器清空本地会话回登录页。
- 服务端会话只存在内存，exe 重启后所有浏览器需要重新登录。

### 3.3 安全边界

- 局域网内是 HTTP，协议层对业务数据做了加密与签名：抓包者只能看到公钥与密文，改不了请求、也重放不了。但**页面本身没有证书保护**，中间人可以返回假网页骗取令牌，所以仍只建议在可信局域网使用，不要把管理端口映射到公网。
- 浏览器端禁止启停网关，也禁止退出应用，避免远程把服务弄停。
- 浏览器端不能执行任何“读写本机文件路径”的操作。

| 额度刷新（单个/全量/按渠道） | ✓ | ✓ |
| API Keys、模型目录、自定义提供商 | ✓ | ✓ |

## 五、移除号池同步

### 5.1 删除范围

| 位置 | 删掉的东西 |
| --- | --- |
| 桌面客户端 | 设置里的「WebDAV 同步」页、「同步时间」页里的号池同步块、反代页的「号池同步」页 |
| 桌面后台 | 网盘传输、号池同步引擎、定时同步、删除墓碑、跨机凭据兜底、设备指纹云端备份 |
| 文档 | README 里同步相关章节 |

### 5.2 三块保留但改变用途

1. **加密信封实现**：不再用于同步压缩包；随同步模块一并删除，如未来需要备份/导出加密，再单独引入。
2. **敏感元数据重新加密**：保留，账号导出/导入仍要正确解密与重加密。
3. **API Key 按原密钥入库**：保留，账号与 Key 的 JSON 导入仍需沿用原密钥。

### 5.3 删除后的确认口径

- 单机全部功能不受影响：转发、选号、冷却、鉴权、日志、统计、模型目录、提供商。
- **定时自动签到保留**：按渠道规则、调度器、号池页「自动签到」弹窗都不动。
- **额度自动刷新保留**。
- **账号与 Key 的 JSON 导出/导入保留**。
- 「同步时间」页改名为「刷新周期」，只留额度刷新周期。
- 不再支持多机自动同步；多台电脑看同一份数据，改为浏览器访问同一台 exe。

## 七、浏览器端实现

### 7.1 复用现有能力

Docker 版的整套管理 API、鉴权、命令表、SSE 事件流、网页控制台静态资源已经存在，把它抽成共享模块，由桌面主进程启动：

- `/api/capabilities`：能力清单（模块、命令的 read/write/deny；read/write 只用于界面判断可用性与置灰，不参与鉴权）
- `/api/rpc`：命令通道，桌面与浏览器共用同一套实现
- `/api/events`：SSE 事件流
- `/api/status`：版本、运行状态
- `POST /api/login`：登录协商（不经过会话校验，只验令牌签名）
- 静态资源：前端构建产物；SPA 路由回退到 `index.html`
- 管理服务的监听地址固定 `0.0.0.0`，与反代数据面的 `bind` 解耦
- 命令表由调用方注入：桌面进程传入全部命令（框架 + 反代），Docker 入口只传反代命令

### 7.2 命令表

- 桌面 IPC 注册的全部命令需要能被 HTTP 通道调用，且共用同一份 handler。命令表由桌面进程注入（框架命令 + 反代命令）；Docker 入口仍只注入反代命令。
- **deny**：启停网关、OAuth 登录、IDE 切号、ZCode 设备操作、打开本机目录、本机文件选择框、日志导出到本机。
- **read**：状态、号池、模型、提供商、Key、日志、统计、配置读取。
- **write**：其余增删改、签到、刷新、配置保存。
- 桌面窗口不受 deny 影响，全部可用；浏览器端不提供“退出应用”命令，退出只能在桌面窗口或托盘操作。

### 7.3 配置读写

- 桌面窗口继续走现有的整份配置保存。
- 浏览器端新增 `proxy_config_get` / `proxy_config_save`，只读写反代配置段：
  - 保护 `channelEnabled`、`checkinAutoRules`、`enableAnthropic`、`enableResponses` 四个由其他操作并发写入的字段，保存时以磁盘为准。
  - 做法：把桌面保存逻辑里“这四个字段取磁盘值”的合并动作抽成公共函数，两处共用。
  - 端口与监听地址：浏览器端保存后不会立即生效（网关不会重启），界面置灰并提示“在桌面端修改并重启网关”。

### 7.4 文件导入

这里说的“文件”特指**账号数据文件**，不是配置文件、也不是备份包。

- 内容：一个 JSON，里面是一个账号或账号数组，字段与桌面版「导出凭据」产出的格式一致（`channel`、`uid`、`name`、`token`、`refreshToken`、`meta` 等）。
- 来源：桌面版号池页「导出凭据」得到的文件，或自己按同样字段整理的 JSON。
- 用途：批量加号、换机、恢复账号；等价于界面上的「粘贴 JSON 导入」，只是内容来自文件。
- 桌面版：可以弹系统文件选择框读路径，支持 JSON 与 ZIP（ZIP 内所有 `.json` 条目合并导入）。
- 浏览器版：只能通过 `<input type="file">` 读到**文件内容**，读不到路径。因此：
  - 只支持单个 `.json` 文件；ZIP 本次不支持（浏览器端没有解压能力，也不为此引入依赖）。
  - 前端读完文件后调用现有导入命令，复用同一套字段解析、去重与入库逻辑。
  - 不需要新增后端上传接口。
- 注意：如果选的是“元数据导出”包（不含 token），导入会被拒绝并提示“该包只有元数据”，与桌面版行为一致。
- 导入后账号立即入池并触发一次额度刷新。

**导入对其他模块的影响**

- 不受影响：模型目录与模型配置、API Keys、自定义提供商定义、历史请求统计。
- 会变化：号池新增账号并可被调度；操作日志新增一条导入记录；额度刷新后积分日历出现该账号的条目；统计的账号维度能看到它，但历史请求数为 0。
- **只新增、不更新**：同渠道同 UID 已存在时跳过，不会用新文件里的 token 覆盖旧账号。要换凭据得先删旧号再导入。
- **提供商必须先存在**：JSON 里的 `channel` 在当前渠道表找不到时会回落到界面选中的渠道，导致账号被归到错误渠道。导自定义提供商的账号前，先建好对应提供商。

### 7.5 实时更新

- 桌面窗口走 IPC 事件（现有）。
- 浏览器走 SSE（现有 `/api/events`，断线退避重连）。
- 需要补两类事件：操作日志写入、请求统计写入。
  - 这两类每个代理请求都会写库，必须节流合并：日志 300 毫秒窗口、统计 500 毫秒窗口，窗口内多次写入只发一条“有新数据”的信号。
  - **合并的只是通知，不是数据**：日志与统计照旧逐条落库，事件体不携带内容。
  - 页面收到后按自增编号拉增量，禁止按时间戳拉（同毫秒多条会互相覆盖）。
- 浏览器内部保留 15 秒兜底轮询，防事件丢失；页面不可见时不执行。

### 7.6 传输加密与登录协商

局域网内是 HTTP，所以浏览器与管理服务之间的**业务数据全部加密，令牌与会话密钥都不上网**。

**密钥派生**

- 令牌侧：`K_token = HKDF-SHA256(令牌, salt="agenthub-admin", info="agenthub-auth")`，只用于登录签名，不用于加密业务数据。
- 会话侧：登录时双方做 ECDH（P-256）临时密钥协商，得到共享密钥；再由共享密钥经 HKDF 派生：
  - 请求密钥 `K_req = HKDF(shared, info="agenthub-req")`
  - 响应密钥 `K_resp = HKDF(shared, info="agenthub-resp")`
  - 签名密钥 `K_sig = HKDF(shared, info="agenthub-sig")`
- 会话密钥不传输，只在双方内存/localStorage 中存在。

**登录流程**（`POST /api/login`，不经过会话校验）

1. 浏览器输入令牌，派生 `K_token`。
2. 浏览器生成一次性 ECDH 密钥对，发送：公钥、时间戳、随机数、`HMAC(K_token, 公钥 + ts + nonce)` 签名。
3. 服务端验证签名、时间窗、随机数，生成自己的 ECDH 密钥对，算出共享密钥。
4. 服务端返回：自己的公钥、`sessionId`、时间戳、随机数、`HMAC(K_token, 公钥 + sessionId + ts + nonce)` 签名；**不返回会话密钥**。
5. 浏览器验证服务端签名，算出同一份共享密钥，派生 `K_req` / `K_resp` / `K_sig`。
6. 浏览器把 `sessionId`、会话密钥与登录时间存入 localStorage；令牌丢弃，不再保存。

登录失败统一返回 401，不区分“令牌错误、签名错误、时间窗过期”。

**请求与响应**

- 每次请求带：`sessionId`、时间戳、随机数、签名、密文。
- 签名 = `HMAC-SHA256(K_sig, sessionId + 方法 + 路径 + 时间戳 + 随机数 + 密文哈希)`。
- 请求体用 `K_req` AES-256-GCM 加密，随机 12 字节 IV。
- 服务端校验：会话存在且未过期、时间戳偏差 ≤ 5 分钟、随机数未用过（5 分钟窗口去重，Map 设上限并定期清理）、签名匹配，任一失败返回 401。
- 成功响应体用 `K_resp` 加密，响应里回带本次请求的随机数；浏览器校验回带的随机数与请求一致，防止响应被重放。GCM 认证标签保证完整性。
- 401/403 等鉴权失败返回明文错误（此时没有可用密钥），文案不透露校验细节。

**SSE**

- 建立连接时带 `sessionId`、时间戳、随机数、签名（覆盖 `GET /api/events + ts + nonce`）。
- 每条事件帧单独用 `K_resp` 加密：`data: {iv, ciphertext}`；浏览器逐帧解密。
- 连接期间会话过期，服务端关闭连接，浏览器回登录页。

**协议层能防什么、不能防什么**

- 能防：被动抓包（只能看到公钥与密文）、请求/响应篡改（GCM 认证 + 签名）、重放（时间窗 + 随机数）、公钥替换（双方公钥都带令牌签名）。
- 不能防：**页面本身被替换**。没有 HTTPS，中间人可以给你返回一个假网页，页面里的脚本就能直接拿到你输入的令牌。所以协议加密不能替代“可信局域网”这个前提。
- 令牌弱时仍可能被离线爆破，但爆破令牌只能用于发起新的登录（还要过时间窗与随机数），不能解开已经建立的会话——ECDH 提供前向保密。

**过期与失效**

- 满 12 小时：服务端拒绝并关闭 SSE，浏览器清空本地会话并回登录页。
- 关闭标签页或重启浏览器：本地会话保留，重新打开仍可继续使用（12 小时内）。
- exe 重启：服务端内存会话清空，浏览器下次请求收到 401，回登录页。
- 用户修改令牌：所有现有会话立即失效。

## 八、界面与状态

- 浏览器登录页：输入管理令牌；令牌错误时统一提示“令牌不正确”，不透露具体校验细节。
- 桌面端「设置」显示：管理地址、当前令牌（掩码显示，可查看/复制/修改）、提示“修改令牌后，所有浏览器需要重新登录”；令牌不允许清空。
- 桌面端「设置」提示关闭窗口的行为：
  - 「最小化到托盘」（**强制开启**，升级时也会被打开）：关窗后进程继续，反代与管理服务都还在，浏览器可继续访问。
  - 用户仍可手动关闭该开关；关闭时界面明确提示“关窗即退出，浏览器与反代都会断开”。
- 浏览器端空状态区分「数据为空」与「加载失败」，后者带重试。
- 浏览器端断线：顶部提示“与服务器的连接已断开，正在重连…”，恢复后提示消失并刷新一次。
- 浏览器端被禁止的操作：按钮置灰 + 原因文案。

## 九、数据兼容与升级

升级方式：**覆盖安装新 exe，数据目录不变**（仍是 `%APPDATA%\AgentHub`）。打开新版本后，原有数据原地继续使用。

### 9.1 配置

- 旧配置里的 `webdavShared`、`webdav.deviceId/deviceName`、`proxy.poolsyncSchedule`、`remoteTargets`、`remoteActiveId` 等字段不再被读取。
- 读取配置时**只补缺失字段，不覆盖已有值**：深合并默认值，已有的主题、端口、账号设置、签到规则、刷新周期一律保留。
- 删除字段不触发整份重写；旧字段留在文件里无害，也可以在下一次正常保存时自然消失。
- 「最小化到托盘」**强制开启**：新用户默认开启，旧配置里明确设为关闭的也在升级时改为开启，保证关窗后反代与管理服务继续运行。界面上仍保留开关，用户可手动关闭，关闭时明确提示“浏览器将断开”。
- 旧配置里没有管理令牌：新版本首次启动自动生成一个 24 字节随机串，设置页可见、可改；不需要用户手工初始化。
- 升级后首次启动会在日志里记一条“已升级到新版本”的记录，方便排查。

### 9.2 数据库

- 表结构不变，不做迁移、不清库。
- 历史请求统计、操作日志、积分日历、账号、Key、提供商全部保留。
- 新增的实时事件只是通知，不写新表、不改旧表。
- 不主动删除数据目录里的历史文件（如同步状态文件、墓碑文件），它们不再被读取，留着无害。

### 9.3 凭据

- 桌面版凭据仍是 `enc:v1:`（Windows DPAPI），同一台电脑、同一 Windows 用户下照常解开。
- 新方案不涉及跨机器、跨容器，所以不存在“密文解不开”的问题。
- 账号与 Key 的导出/导入格式保持不变，旧导出的 JSON 仍可导入。

### 9.4 升级验证

1. 用旧版本产生数据（账号、Key、提供商、日志、统计、改过的配置）。
2. 覆盖安装新版本，启动。
3. 核对：账号与凭据可用、Key 仍能通过校验、提供商与模型别名保留、日志与统计完整、主题与端口等设置保留、签到规则保留。
4. 浏览器访问，看到的是同一份数据。
5. 确认配置文件中旧字段没有导致启动报错或输入被重置。

## 十、不做什么

- 不做 Docker 场景的目标适配；`gateway/` 代码保留可用（与桌面共享核心），只是不属于本次目标。
- 不做号池同步、定时同步、双向同步。
- 不做桌面客户端连远程实例。
- 不做多用户与权限体系（只有“有令牌 / 没令牌”）。
- 不允许浏览器启停网关或退出应用。
- 不在浏览器端做 OAuth、IDE 切号、ZCode 设备操作。
- 不把管理端口设计为可公网访问；不提供 HTTPS（建议只在可信局域网使用）。

## 十一、风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 管理端口（反代端口 + 1）被占用 | 管理服务启动失败，浏览器不可用 | 启动时检测并明确提示；提供“改反代端口”的引导 |
| Windows 防火墙拦截 | 局域网浏览器访问不了 | 首次监听提示放行；文档写明 |
| 令牌泄漏或过弱 | 局域网内他人获得完全控制 | 手动设置至少 16 位；令牌加密存盘、不写日志；不上网；修改后所有会话立即失效 |
| 令牌被暴力猜测 | 可发起新的登录，但**解不开已建立的会话**（ECDH 前向保密） | 至少 16 位；时间窗与随机数防重放；改令牌立即踢掉全部会话 |
| 会话密钥泄漏 | 12 小时内可冒用 | 存 localStorage（方便多标签页共享）；服务端 12 小时强制过期；改令牌立即踢掉所有会话 |
| 页面可被替换 | 没有 HTTPS，中间人可返回假网页骗取令牌 | 只建议可信局域网，禁止映射公网；需要更强安全时再加 HTTPS |
| 桌面进程退出 | 反代与浏览器一起断 | 「最小化到托盘」强制开启；用户手动关闭时界面给出明确提示 |
| 升级改写用户设置 | 用户原本关着托盘，升级后被打开 | 这是为保证网页控制台可用而做的取舍；界面保留开关，可随时手动关闭 |
| 浏览器端误操作 | 例如批量删号、清空统计 | 危险操作二次确认；写操作需要完整令牌 |
| 浏览器与桌面同时改同一项 | 后保存的覆盖先保存的 | 配置保存以磁盘为准合并关键字段；其余操作即时生效，冲突概率低 |

## 十二、附录 A：实现要点（给开发看，产品阅读可跳过）

### A.1 管理服务

- 新模块 `electron/backend/admin.cjs`：创建 express 应用，挂载 `/api/*` 与静态资源，监听 `0.0.0.0:<反代端口 + 1>`。
- 路由与命令表从现有 Docker 入口（`gateway/src/index.cjs`）抽取，避免两份实现：
  - 抽出 `registerAuth`、`registerRpcRoutes`、`registerEventRoutes`、`registerStatusRoutes`、静态资源挂载。
  - Docker 入口改为调用同一模块，只是监听参数与运行形态不同。
- 静态资源目录：开发态指向项目 `dist`，打包态优先 `app.getAppPath()/dist`；asar 内读取有问题时改为 `asarUnpack` 或放到 `resources` 外。非 `/api/*` 且无静态文件的路径回退到 `index.html`（SPA）。
- 反代端口变更时，管理服务需要随之重启（桌面端改端口后调用重启逻辑）；新端口 +1 被占用时回滚并提示。
- 反代端口为 0 或 65535 时拒绝保存并提示（+1 无意义或溢出）。

### A.2 鉴权与会话

- 首次启动用 `crypto.randomBytes(24).toString("hex")` 生成初始令牌并写入配置（`encryptSecret` 加密，与 WebDAV 密码同机制）；之后只在用户手动修改时变化。
- 管理服务固定绑 `0.0.0.0`，与反代 `bind` 解耦；监听失败时反代不受影响，桌面弹出提示。
- 登录走 `POST /api/login`：服务端用 `node:crypto` 的 `generateKeyPairSync("ec", { namedCurve: "prime256v1" })` 生成临时密钥对，与客户端公钥做 `diffieHellman`，共享密钥经 HKDF 派生 `K_req` / `K_resp` / `K_sig`。会话对象 `{ id, kSig, kReq, kResp, createdAt, expiresAt }` 存内存 Map，有效期 12 小时。
- 登录请求校验：`HMAC(K_token, 公钥 + ts + nonce)`；登录响应同样带 `HMAC(K_token, 公钥 + sessionId + ts + nonce)` 签名，防止公钥被替换。
- 后续请求：校验会话未过期、时间戳（±5 分钟）、随机数去重（内存 Map，5 分钟清理，设条数上限防内存耗尽）、`HMAC(K_sig, sessionId + ...)` 匹配；任一失败返回 401。
- 修改令牌：清空全部会话，现有 SSE 连接关闭。
- 浏览器把 `sessionId`、会话密钥（导出为原始字节后 base64）与登录时间存 `localStorage`；令牌不存浏览器。401 时清空并回登录页。
- 令牌与会话密钥都不写日志、不进崩溃日志。
- 定时清理过期会话与过旧随机数；并发会话数设上限，超出时淘汰最旧会话。
- 会话密钥用于 HMAC/AES 前需要 `importKey`，不要缓存 CryptoKey 到 localStorage。

### A.3 命令表与形态门控

- 把桌面 `ipc.cjs` 的注册抽成可注入的 `handle` 收集器，同时供 IPC 与 HTTP 使用（Docker 已有同类做法，扩到框架命令）。
- `commands.cjs` 的 `DENY` 增加浏览器端条目：`proxy_start`、`proxy_stop`、`proxy_restart`、`proxy_oauth_begin`、`proxy_oauth_submit_callback`、`proxy_ide_status`、`proxy_ide_switch`、`proxy_zcode_*`、`proxy_open_data_dir`、`proxy_open_rules_dir`、`proxy_account_import_file`、`proxy_oplog_export`。

- 桌面窗口走 IPC 时不套用 deny（保持现状），HTTP 通道套用。

### A.4 新增命令

1. `npm run build`。
2. `node scripts/dev-sink-golden.cjs`。
3. `node tools/gateway-closure-check.cjs`。
4. 启动 exe，确认反代端口与管理端口（+1）都在监听。
5. 桌面窗口功能逐项回归：号池、签到、刷新、Key、模型、提供商、配置、日志、统计。
6. 局域网另一台电脑用浏览器打开管理地址，输入令牌登录。
7. 浏览器端逐项验证：号池增删改、签到、刷新、Key、模型、提供商、配置读写、日志、统计。
8. 浏览器端确认启停网关、OAuth、IDE、ZCode、打开目录、本机文件框均被拒绝并显示原因。
9. 浏览器端上传账号 JSON 文件导入成功。
10. 桌面端 OAuth 登录成功，浏览器端能看到新账号。
11. 桌面与浏览器同时在线：桌面改号后浏览器自动刷新；浏览器改配置后桌面生效。
12. 发一次请求，浏览器的日志与统计在 2 秒内更新；50 并发下事件频率被节流。
13. 关闭「最小化到托盘」后关窗，确认进程退出、浏览器断开；开启后关窗，确认浏览器仍可访问。
14. 重启 exe，确认令牌保持不变；重启后浏览器因服务端会话清空需要重新登录；修改令牌后，确认所有浏览器立即失效并回到登录页。
15. 加密校验：浏览器开发者工具看请求与响应，登录阶段只应看到两个公钥与签名，**看不到令牌或会话密钥**；业务请求的 `args`/数据应为密文；把请求重放一次，确认服务端拒绝（随机数已用过）。
16. 会话校验：关闭标签页或重启浏览器后重新打开，确认仍在登录态；同一浏览器新开标签页，确认共享登录、无需重复输入。服务端到 12 小时后确认回到登录页（可临时改短验证）。
17. 过期校验：把会话有效期临时改短（如 1 分钟）验证到点后回登录页，再改回 12 小时。
18. 管理端口被占用时，确认启动提示明确。
19. 用旧版本的数据覆盖安装新版本，按第九章「升级验证」逐项核对：账号、Key、提供商、日志、统计、主题、端口、签到规则全部保留，配置里残留的旧字段不导致启动报错，「最小化到托盘」被改为开启。

| # | 决策 | 结论 |
| --- | --- | --- |
| 1 | 运行形态 | 只考虑 Windows exe，不做 Docker 场景 |
| 2 | 网页控制台 | 桌面 exe 内置，局域网浏览器访问 |

| 12 | 文件导入 | 浏览器上传文件内容，复用现有导入命令；不新增上传接口 |

| 18 | 传输加密 | 选 B2 并升级为 ECDH：令牌与会话密钥都不上网，公钥交换用令牌签名防替换，请求/响应/SSE 全加密，时间窗 + 随机数防重放 |
| 19 | 登录会话 | 令牌只用于登录时的公钥签名；ECDH 协商出 12 小时会话密钥；会话存 localStorage（多标签页共享），时效由服务端强制 |
