# AgentApiGateway —— 反代网关

<p align="center">
  <a href="./README.md">简体中文</a>
</p>

> 把订阅额度变成标准 API，任何客户端都能调。

AgentApiGateway 是本地运行的反代网关（Electron + Vue 3 + TypeScript），自身不带模型：把你本机已登录的 AI 编程工具订阅额度包成 OpenAI 兼容 API，配号池自动切换、额度签到与用量统计。

它有两个形态：**Windows 桌面版**（网关 + 图形界面，见 [Windows 版下载与安装](#windows-版下载与安装)）和 **Docker 版**（headless 常驻，适合放到服务器上，见 [Docker 版下载与安装](#docker-版下载与安装)）。

| 能力 | 一句话 | 适合谁 |
| --- | --- | --- |
| **反代网关** | 把本机已登录的订阅额度包成标准 API，任何客户端都能调 | 手里有订阅额度（Trae / WorkBuddy / 小浣熊 / 魔搭 / ZCode / Qoder / Cline 等 14 个渠道）、想让别的软件也用上的人 |

## Windows 版下载与安装

### 安装版

1. 打开 [Releases 页面](https://github.com/HUIdada1/AgentHub/releases/latest)
2. 下载 `AgentApiGateway-Setup-x.y.z.exe`
3. 双击安装。安装过程中可以改安装目录，装完会在桌面和开始菜单创建「AgentApiGateway」快捷方式
4. 启动后程序常驻系统托盘，关窗口不会退出；托盘图标双击可唤回窗口，右键菜单里能看到网关状态

### 系统要求

- Windows 10 / 11（x64）
- 不需要预装 Node、浏览器等任何依赖，运行时已打包在内
- 需要本机登录过对应客户端（号池里要接入对应渠道的账号）

### 数据与备份

- 所有配置与数据都存在 `%APPDATA%\AgentHub`，卸载程序不会删除它
- 左下角「设置」= 全局项（通用 / WebDAV 同步 / 同步时间）；反代网关右上角还有一个「配置」按钮，管的是网关自己的设置

## Docker 版下载与安装

Docker 版是 **headless 形态的反代网关**，适合把网关丢到服务器上常驻。渠道代码与桌面版同一套，账号通过 WebDAV/S3 号池同步互通；镜像自带 **Web 控制台**，浏览器打开服务器地址就能管号池、Key 和渠道。

前提：Docker 20.10+ 与 Compose v2，Linux 服务器 1 核 512MB 起。

```bash
git clone https://github.com/HUIdada1/AgentHub.git && cd AgentApiGateway

# 凭据加密密钥，务必留存好：丢了以后已加密的凭据不可恢复
export AGENTHUB_SECRET_KEY=$(openssl rand -base64 32)

# 容器内以 uid 1000 运行，宿主数据目录属主要对齐
mkdir -p gateway-data && sudo chown 1000:1000 gateway-data

docker compose -f gateway/docker-compose.yml up -d --build
```

起来后自检：

```bash
curl -s http://127.0.0.1:9528/api/livez     # {"ok":true}，进程活着
curl -s http://127.0.0.1:9528/api/readyz    # 503 = 池里还没账号，正常
```

- 浏览器打开 `http://<服务器>:9528/` 即 **Web 控制台**（需先设 `AGENTHUB_ADMIN_TOKEN`，登录时输入的就是它）
- 客户端连 `http://<服务器>:9527/v1`，Key 在控制台里建，也可以用管理 API（`POST /api/keys`）
- 管理 API 与 Web 控制台默认只绑宿主 `127.0.0.1:9528`；设了 `AGENTHUB_ADMIN_TOKEN` 才能从外部访问
- 账号来源：桌面版配好 WebDAV 后同步过去（推荐），或 `POST /api/accounts/import` 导入 JSON
- 容器里没有桌面客户端，**本机软件导入、切到 IDE、Qoder 双区**这些依赖 Windows 客户端的能力用不了
- 别把桌面版的数据目录挂给容器：那边凭据是 DPAPI 密文，Linux 侧解不开

端口、备份、密钥轮换、WebDAV 与容器同机部署、排障等完整说明见 [gateway/README.md](./gateway/README.md)。

## 反代网关

> 这是本项目最核心的板块：把**本机已经登录**的订阅额度包成标准 API，任何支持「自定义接口」的客户端都能直接调用。
>
> 入站三条协议面，**同一个地址、同一把 Key**，按客户端讲的协议自动分流：
>
> | 端点 | 协议 | 谁会用 |
> | --- | --- | --- |
> | `POST /v1/chat/completions` | OpenAI Chat Completions | Cherry Studio / ChatBox / NextChat / Cline / Roo Code 等「OpenAI 兼容」客户端 |
> | `POST /v1/messages`（另有 `POST /v1/messages/count_tokens`） | Anthropic Messages | Claude Code / Anthropic SDK |
> | `POST /v1/responses` | OpenAI Responses | Codex CLI |
>
> 三条面共用同一套调度：鉴权、模型别名、模型禁用、回退链、号池换号、冷却决策与记账完全一致，区别只在「怎么读网关 Key」和「写成什么字节」。所以 **Claude Code 与 Codex 可以直接把网关地址填进去，用到全部渠道**，不必再经 CC Switch 做协议翻译。

### 支持的渠道

| 渠道 | 对应订阅 | 登录形态 | 签到 |
| --- | --- | --- | --- |
| **Trae SOLO CN** | Trae SOLO 国内版 | 官方授权页 + 本机回环回调 | 每日签到 |
| **WorkBuddy CN** | WorkBuddy 国内版 | 官方登录页 + 本机轮询 | 每日签到 |

| **Qoder CN** | Qoder 国内版 | 官方登录页设备码轮询（无需本机客户端）/ 从本机软件导入 | 每日领 Credits |

| **AutoClaw 国际版** | AutoGLM 国际站 | OAuth 授权登录（含风控验证）/ 从本机导入 | 每日签到领积分 |
| **Cline Free** | Cline 免费额度池 | WorkOS 设备授权（浏览器确认，**无需安装客户端**）/ 从本机 Cline 客户端导入 / 粘贴凭据 | 无签到活动 |
| **Cline Pass** | ClinePass 订阅池 | 同上（同一份 Cline 登录态可在两个渠道各导入一次） | 无签到活动 |

各渠道的号池、签到、策略完全独立，互不影响：在号池页顶部切换渠道，下方整块区域只显示当前渠道的账号。

> **Cline 双渠道（Free / Pass）说明**
>
> - Cline 是**标准 OpenAI 兼容上游**（`api.cline.bot`），无签名、无桌面端依赖：设备授权登录在浏览器里点一次确认即可，凭据自动续期（access token 每小时轮换）。
> - **Free 与 Pass 是两个独立渠道**，不是「一个渠道的两种模式」：两个池的账号、模型清单、启停、映射互不影响。免费池有每日免费额度（余额单位 Credits，欠费时显示负值）；订阅池只对开通了 ClinePass 的账号开放模型。
> - 模型 id 带池前缀（如 `cline-free/deepseek-v4.1-flash`），那是上游的**计费通道选择器**，网关按原样转发；客户端用不带前缀的短名（`deepseek-v4.1-flash`）请求时会自动补上本渠道的池前缀。请求模型无权限时上游返回 403（未订阅该模型/仅官方产品面可用），网关如实透传不重试、不冷却账号——换一个模型或换一个渠道试试即可。

> **Qoder 渠道的两点特别说明**
>
> - **推理依赖本机安装的 Qoder 客户端**：该渠道每个请求的签名头与请求体编码都由客户端内置的 wasm 实时生成（无法手工构造）。AgentApiGateway 会在首次调用时从已安装客户端中提取这部分能力并按版本缓存（客户端升级自动重建，无需重装 AgentApiGateway）。因此**只导入凭据、没装对应客户端时，账号可入池但无法发起请求**——建议保持客户端处于安装状态，安装目录放在默认位置或客户端自带启动器的默认路径均可（自定义安装路径也能自动识别）。
> - **每日 Credits**：号池页的按钮是「领 Credits」（每天 100，10:00 UTC+8 刷新，领取后 30 天有效，重复点击按"今日已领"处理）；领取接口要求客户端自带的风控身份，故同样需要本机安装客户端。国际版免费额度不含 DeepSeek / GLM Flash 系列，需订阅覆盖才有可用模型。

### 页面构成

| 页面 | 作用 |
| --- | --- |
| 总览 | 网关服务开关、接入地址与端点复制；用量统计：时间区间可选（今天 / 7 天 / 30 天 / 90 天 / 自定义）、KPI 与趋势（请求数 / Token / 成功率 / 延迟多指标切换，悬停看精确数值）、Token 构成与请求状态环形图、用量占比 TOP（渠道 / 模型 / Key / 账号 × 按请求 / 按 Token，含请求与响应 token 分列）、各 Key 用量、明细（Key / 模型模糊搜索 + 渠道 / 状态筛选）；流水保留期可配（默认 90 天） |
| 号池 | 按渠道管理账号：状态、余额、套餐到期、策略、添加账号、一键签到、切到 IDE |
| API Keys | 生成/停用 Key，配置日配额与限速；完整 Key 随时可查看复制 |
| 模型目录 | 全渠道模型合并视图，逐模型启停、指定渠道、设置倍率与别名；各渠道官方目录可一键从云端拉取 |
| 号池同步 | 多台电脑共享号池：账号与凭据打包经 WebDAV 同步，可选只同步某一个渠道 |
| 日志 | 请求流水与操作日志，可筛选、导出 Excel |

### 上手教程

#### 第 0 步：准备一个上游账号

在电脑上装好并用你自己的账号登录至少一个上游客户端（Trae SOLO CN / WorkBuddy / 商汤小浣熊 / ZCode / Qoder 任一）。如果你已经在本机登录过，第 2 步可以直接「从本机软件导入」，连登录都不用重新做——Qoder 的登录凭据存在加密信封里，AgentApiGateway 也能直接读取（需与客户端同一 Windows 用户）。

#### 第 1 步：启动网关服务

打开「反代网关 · 总览」，点右上角的**启动服务**，状态变成 `RUNNING` 即为就绪。默认监听：

```
http://127.0.0.1:9527/v1
```

这个地址只会先给本机用。端口、绑定地址（想让局域网其他设备访问就把 `127.0.0.1` 改成 `0.0.0.0`）都在「配置 · 反代网关」里改，改完需要重启服务。

#### 第 2 步：往号池里加账号

进入「反代网关 · 号池」，先在顶部选中渠道，再点**添加账号**。每个渠道都支持四种添加方式，挑一种就行：

1. **OAuth 登录**（最推荐）——跳转官方授权页登录，登录完成后自动入池，全程不用手工填任何 token：
   - Trae SOLO CN：授权后会回调本机回环地址；万一浏览器停在回调页没自动跳回，把地址栏内容整段粘到输入框兜底
   - WorkBuddy 两个版本：登录完本机自动轮询结果，无需任何粘贴
   - 商汤小浣熊：授权窗在 AgentApiGateway 应用内弹出，授权码由应用直接截获；被拦截时可粘贴 `office-raccoon://auth/callback?code=…` 兜底
   - ZCode：跳 Z.ai 授权页，登录后自动入池；随后后台会用几十秒初始化套餐并解析编码套餐 API Key
   - Qoder 两个版本：跳官方登录页（qoder.cn / qoder.com）完成登录，本机每秒轮询直接取回设备凭据对，**无需本机安装客户端、也不用粘贴回调**
   - LobsterAI（有道龙虾）：跳官方登录页（lobsterai.youdao.com）登录，回调本机回环地址自动入池，**无需安装客户端**；浏览器没跳回时把地址栏内容整段粘回兜底（3 分钟超时后也仍认这段回调）
   - Cline 双渠道：跳 WorkOS 设备授权页（已带用户码，点一次确认即可）完成登录，本机自动轮询入池，**无需安装客户端、不占用本地回调端口**
   - 每次登录对应一个账号，想加几个号就重复几次
2. **从本机软件导入** —— 直接扫描本机已登录客户端的凭据，零请求入池，最省事（Qoder 走的也是这条：从客户端登录态里读出设备令牌）
3. **从 JSON / ZIP 文件** —— 批量导入别人给你的账号文件
4. **粘贴 JSON** —— 手动粘贴单条或一组凭据

账号加进来后，号池列表里能看到它的余额、套餐到期时间和状态（online / cooling / exhausted / relogin / disabled）。想主动养护账号，点该渠道的**一键签到**（或领加油包，Qoder 是「领 Credits」）；也可以打开定时自动签到，每天到点自动跑全渠道。

#### 第 3 步：生成 API Key

进入「API Keys」页，点生成：

- **名称**：随便起，方便自己认，比如 `cherry-studio`
- **路由**：默认 `auto` 会按号池策略自动挑渠道；也可以锁死只走某一个渠道
- **日配额 / 限速**：不填即不限；按需设置可以防止某个客户端把额度跑光

生成的 Key 会立刻弹出来给你复制；之后也能在列表里随时「查看 / 复制」完整 Key（经 DPAPI 加密存库），所以不用怕一次没存住。真泄露了就把它停用（开关即时生效）再生成一个新的。

#### 第 4 步：在客户端里填三项

任何支持「OpenAI 兼容 / 自定义 OpenAI 接口」的客户端都行（Cherry Studio、ChatBox、NextChat、Cline、Roo Code、各类 IDE 插件……）：

| 项目 | 填什么 |
| --- | --- |
| API 地址（Base URL） | `http://127.0.0.1:9527/v1`（部分客户端只要求填到端口，按它的提示来） |
| API Key | 第 3 步生成的 `sk-` 开头的 Key |
| 模型 | 从「模型目录」页里挑一个可用的模型名 |

保存后发一句话测试，回到「总览」看到实时请求流里出现记录，就说明链路通了。

> **给 Claude Code / Codex / Claude Desktop 用？** 网关听得懂它们的原生协议，可以直接把网关地址填进去（见本节开头的三条入站协议面）。

#### 第 5 步（可选）：接入 Claude Code / Codex

- **Claude Code / Anthropic SDK**：`ANTHROPIC_BASE_URL` 填 `http://127.0.0.1:9527`（不要带 `/v1`），`ANTHROPIC_AUTH_TOKEN` 填第 3 步生成的 Key
- **Codex CLI**：`~/.codex/config.toml` 里把 provider 的 `base_url` 填 `http://127.0.0.1:9527/v1`、`wire_api = "responses"`（Codex 已移除对 `chat` 的支持，写 `chat` 会直接报错）
- 模型名从「模型目录」页里挑一个可用的填上即可

### 号池与自动切换

- **五态状态机**：online（可用）/ cooling（冷却中）/ exhausted（额度耗尽）/ relogin（需重新登录）/ disabled（手动停用）
- **池内策略**：到期优先（默认，先把快过期的额度用掉）/ 余额优先 / 轮询，按渠道单独设置
- **运行期自动换号**：上游返回 402 / 额度类错误时自动换下一个号（单请求最多换 2 次）；已知零余额的号在调度时直接跳过
- **冷却表**：不同错误按不同时长冷却（限流 60 秒、服务端错误 10 分钟、次日额度类错误等到次日 04:00、401 标记为需重新登录），避免死号被反复重试
- **模型回退**：模型未知或全部号不可用时，按「配置 · 反代网关」里设置的全局回退模型自动切换

### 切到本机 IDE（可选）

号池里每个账号都有一个「切到 IDE」按钮：把该账号写成本机客户端的当前登录态，适合「号池里的号想直接在本机客户端里用」。

- 支持 WorkBuddy 双区、商汤小浣熊、ZCode。**Trae 不支持**——它的登录态是绑定设备密钥的加密信封，构造不出合法文件，程序会直接说明原因，不会硬写
- 点击后会弹确认框，确认即自动：关闭客户端 → 备份原登录态 → 写入 → 重新打开客户端
- 写入前后有多道校验（防并发回写、写后回读校验失败自动回滚）；ZCode 采用合并式写回，不会动你的远程连接地址；小浣熊会保留账号专属设备指纹，避免跨号串号导致旧号被吊销

### 连接远程网关（可选）

服务器上用 Docker 版常驻网关时，桌面版可以在「反代网关 → 配置 → 远程实例」里连上它：填地址（`http://<服务器>:9528`）和管理令牌（服务器上的 `AGENTHUB_ADMIN_TOKEN`），测试通过后，反代页右上角的切换按钮可以在「本机 / 远程」之间切换——切到远程后，反代板块所有页面对的就是那台服务器，建 Key、改渠道、触发签到这些操作都在桌面界面里完成；容器里做不了的事（启停网关、IDE 切号、打开目录）会直接说明原因。

日常监视建议在服务器上另设只读令牌 `AGENTHUB_ADMIN_READONLY_TOKEN`（只能看不能改）；`http` 地址仅限内网，公网请给 9528 配 https——管理令牌不能明文出网。

### 多台电脑共享号池

「号池同步」页把账号与凭据打包（用统一 WebDAV 密码 AES-256-GCM 加密）传到 WebDAV，另一台电脑拉下来即可共用同一批号。可以选择同步全部渠道，也可以只同步某一个渠道；进度按阶段展示，中途可看细节。

### 防监测与稳定性

- 请求指纹（UA、设备头、链路追踪头、来源 referer）逐字段对齐官方客户端
- WorkBuddy 侧会做指纹清洗（剥离 `cc_*` / `x-anthropic-*`、审核模板最小改写，模板外置可热更新）
- 请求间有 40~220ms 的拟人化随机抖动，换号痕迹不会外泄
- 规则热加载：`rules/*.json`（模型映射 / 清洗模板 / 渠道头）改完即时生效，无需重启

## 常见问题

**Q：客户端连不上网关怎么办？**
先看三处：① 「总览」页服务状态是不是 `RUNNING`；② 客户端填的地址是不是以 `/v1` 结尾；③ Key 有没有停用。再看错误码：`401` 是 Key 不对，`429` 是该 Key 触发了限速或当日配额，`400` 是请求参数有问题，`502` 是上游返回异常（号池会自动换号重试），`503` 是当前渠道没有可用账号（去号池看看是不是全都在冷却或需重新登录）。

**Q：手机上/另一台电脑能访问吗？**
可以。「配置 · 反代网关」把绑定地址改成 `0.0.0.0`，重启服务，然后用局域网 IP + 端口访问。注意这意味着同网段的设备都能访问，请务必设置 Key 的日配额与限速。

**Q：为什么 Trae 不能「切到 IDE」？**
Trae 的本地登录态是 ByteCrypto 加密信封，绑定了设备密钥，无法在外部构造出合法文件。程序会诚实提示而不是写坏你的登录态。

**Q：小浣熊多账号要注意什么？**
多账号入池请统一在 AgentApiGateway 的「OAuth 登录」里做。**不要在电脑端小浣熊软件里点「退出登录」**——商汤服务端会因此吊销旧号凭证，导致号池里的旧账号失效。

**Q：号池用 WebDAV 同步到第二台电脑后，小浣熊账号显示「需重登」怎么办？**
不用重新登录，先让它自己缓过来：小浣熊的刷新令牌是一次性轮换的（第一台每刷一次，同步过去的那份就会作废），v1.68.1 起刷新被服务端拒绝时会自动到其他设备把最新凭据取回来重试，第一台下次刷新也会立刻回传，所以**保持两台都开着、网络与 WebDAV 正常，等一轮额度刷新（默认 30 分钟）即可**。同一账号请只在 AgentApiGateway 里登录一次：**不要在第二台电脑上用 OAuth 或客户端再登录同一个号**——那会产生第二个会话（服务端按会话互踢），连第一台也会一起掉。真掉登录时账号气泡会说明原因（服务端拒绝 / 并发抢刷 / 疑似在别处重新登录）。

**Q：点「切到 IDE」会不会打断我正在用的客户端？**
会：程序需要先关闭对应客户端，写入登录态后再自动打开（这也是为什么每次都会先弹一个确认框）。如果你此刻正在那个客户端里干活，先存盘再点。

**Q：我的凭据安全吗？**
账号 token 经 Windows DPAPI 加密后落盘，且只在主进程中流转，不暴露给界面层；网关的 API Key 在库里只存 SHA-256 哈希（完整 Key 单独用加密信封保存，供你自己查看）。所有请求只发往你所用服务的官方接口，以及你自己配置的 WebDAV 服务器，中途不经过任何第三方服务器。

**Q：没配置 WebDAV 是不是很多功能不能用？**
不是。号池同步是多台电脑共享号池用的，单机网关的全部功能不依赖 WebDAV。

**Q：自动签到什么时候跑？**
默认关闭。开启后每天到设定时间（默认 09:00，可改）自动给全部渠道跑一遍签到/领加油包，结果按渠道分别记录，切渠道看得到各自的历史。

```bash
# 环境：Node >= 18
npm install

npm run dev          # 桌面端开发（Electron + Vite HMR）
```

反代网关后端全链路自测（含假上游端到端：换号 / 自动切换 / 流式双态 / 指纹头）：

```bash
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe tools/proxy-smoke.cjs
```

三条入站协议面各自的回归闸（真实 HTTP 打进真调度核心，只桩上游与号池；纯 Node，不需要 Electron）：

```bash
node scripts/dev-sink-golden.cjs         # OpenAI 通路：16 场景的响应字节 / 冷却决策 / 选号顺序 / 流水与基线逐字相等（动调度核心前后必跑）
node scripts/dev-anthropic-in-test.cjs   # /v1/messages：归一 + 事件序 + 错误外壳 + 止血开关
node scripts/dev-responses-in-test.cjs   # /v1/responses：归一 + 事件序 + Codex 三条硬约束 + 止血开关
```

Qoder 渠道专项自测（离线，默认不联网、不消耗额度；凭据与签名器相关断言需要本机装有 Qoder 客户端）：

```bash
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe tools/proxy-qoder-adapter-selftest.cjs      # 适配器纯函数 + SSE 信封解包
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe tools/proxy-qoder-integration-selftest.cjs  # 每日领取（stub）
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe tools/proxy-qoder-selftest.cjs              # 凭据解密 + wasm 签名器
```

Cline 双渠道专项自测（离线 + 本地假上游，不联网、不消耗额度）：

```bash
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe tools/proxy-cline-selftest.cjs   # 协议断言 + 假上游端到端
```

Docker 形态闭包自检（防 COPY 缩水后无人察觉）：

```bash
node tools/gateway-closure-check.cjs   # gateway 运行时依赖闭包清点（下限 108）
```

代码结构：

```
electron/            主进程
  backend/
    proxy/           反代网关（存储 / 适配器 / 号池 / 网关服务 / 规则热加载 / IDE 切换）
      protocols/     入站与出线协议面（openai-out / anthropic-in+out / responses-in+out）
  main.cjs           应用入口（窗口 / 托盘 / 更新）
src/                 渲染层（Vue 3）
  views/proxy/       反代网关页面
  components/        公共组件（侧栏 / 页签 / 配置中心）
```

反代网关的协议细节来自对官方客户端的逆向分析，代码独立实现。
